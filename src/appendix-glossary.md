# Glossary

Every word the book teaches, with a short reminder of what it means and a link to the lesson where it first shows up.

## Java

- **Address**: what an object variable really holds. It says where the object is stored in memory, not the object itself. ([Objects Working Together](ch01-09-objects-working-together.md))
- **Annotation**: a label that starts with `@`, like `@Override` or `@Teleop`, that tells Java something about the code under it. ([Inheritance](ch01-11-inheritance.md), [Your First Robot Project](ch02-01-first-robot-project.md))
- **Array**: a list of values with a fixed size, like `int[]`. ([Lists](ch01-19-lists.md))
- **`ArrayList`**: a list that can grow and shrink. ([Lists](ch01-19-lists.md))
- **`boolean`**: a type that's either `true` or `false`. ([Variables](ch01-02-variables.md))
- **Casting**: turning a value into a different type, like `(int) 3.7`. ([Decimals and Math](ch01-14-decimals-and-math.md))
- **Class**: a blueprint for making objects. ([Classes and Objects](ch01-03-classes-and-objects.md))
- **Child class**: a class that `extends` another one and gets all of its fields and methods. ([Inheritance](ch01-11-inheritance.md))
- **Class variable**: another name for a `static` field, which belongs to the class instead of to each object. ([Static and Constants](ch01-13-static-and-constants.md))
- **Comment**: a note for people reading the code, after `//`. Java ignores it. ([Your First Program](ch01-01-first-program.md))
- **Constant**: a `static final` variable, named in ALL CAPS, that holds a number or value that never changes. ([Static and Constants](ch01-13-static-and-constants.md))
- **Constructor**: the code that runs when an object is made with `new`. ([Constructors](ch01-05-constructors.md))
- **Debugger** and **breakpoint**: VS Code's tool for pausing a running program to look inside it, and the red dot that marks where it pauses. ([Finding Bugs](ch02-10-finding-bugs.md))
- **`double`**: a type for numbers with decimals. ([Variables](ch01-02-variables.md), [Decimals and Math](ch01-14-decimals-and-math.md))
- **Enum**: a type with a fixed set of choices, like `ArmPosition`. ([Enums](ch01-17-enums.md))
- **`equals`**: a method that checks whether two objects are the same in value, like two `String`s with the same letters. ([Objects Working Together](ch01-09-objects-working-together.md))
- **Exception**: an object Java throws when something goes wrong. If nothing catches it, the program crashes. ([Finding Bugs](ch02-10-finding-bugs.md))
- **Field**: a variable that belongs to an object, and lasts as long as it does. ([Fields](ch01-04-fields.md))
- **`final`**: can't be changed after it's set. ([Protecting Your Fields](ch01-12-protecting-your-fields.md))
- **`for` loop**: a loop that counts, with everything about the counting on one line. ([Loops](ch01-18-loops.md))
- **For-each loop**: a loop that goes through every item in an array or list, like `for (Player player : team)`. ([Lists](ch01-19-lists.md))
- **Functional interface**: an interface with exactly one method, which a lambda can stand in for. ([Lambdas](ch01-16-lambdas.md))
- **Getter** and **setter**: a method that hands back a field, like `getHealth()`, and one that changes a field, like `setStance(...)`. ([Protecting Your Fields](ch01-12-protecting-your-fields.md))
- **If statement**: code that only runs when a question is `true`. ([If Statements](ch01-07-if-statements.md))
- **`import`**: lets a file use a class from another package. **`import static`** lets it use a static field or method without its class's name. ([Lists](ch01-19-lists.md), [Units](ch02-03-units.md))
- **Index**: a position in an array or list, starting from 0. ([Lists](ch01-19-lists.md))
- **Infinite loop**: a loop whose question never becomes `false`, so it never ends. ([Loops](ch01-18-loops.md))
- **Inheritance**: one class getting everything from another with `extends`. ([Inheritance](ch01-11-inheritance.md))
- **Instance**: another name for an object. ([Classes and Objects](ch01-03-classes-and-objects.md))
- **Integer division**: dividing two `int`s, which throws away the remainder. ([Decimals and Math](ch01-14-decimals-and-math.md))
- **Interface**: a list of methods that a class promises to have, with `implements`. ([Interfaces](ch01-15-interfaces.md))
- **Iteration**: one time through a loop. ([Loops](ch01-18-loops.md))
- **Lambda**: a small piece of code you can hand around like an object, like `() -> bob.attack(alice)`. ([Lambdas](ch01-16-lambdas.md))
- **Loop variable**: the variable that counts in a `for` loop, usually named `i`. ([Loops](ch01-18-loops.md))
- **Magic number**: a number in the code with no name to say what it means. Give it a name with a constant instead. ([Static and Constants](ch01-13-static-and-constants.md))
- **Method**: something an object can do. ([Methods](ch01-06-methods.md))
- **Method reference**: a shortcut for a lambda that just calls one method, like `bob::isInDanger`. ([Lambdas](ch01-16-lambdas.md))
- **`null`**: "nothing at all," for an object variable that doesn't hold an object. ([Objects Inside Objects](ch01-10-objects-inside-objects.md))
- **Object**: one thing made from a class, with `new`. Also, `Object` is the class every class secretly extends. ([Classes and Objects](ch01-03-classes-and-objects.md), [Protecting Your Fields](ch01-12-protecting-your-fields.md))
- **`Optional`**: a box that might hold a value or might be empty. ([Driving](ch02-09-driving.md))
- **Overloading**: two methods with the same name but different parameters. ([Objects Working Together](ch01-09-objects-working-together.md))
- **Overriding**: a child class writing its own version of a parent's method, marked with `@Override`. ([Inheritance](ch01-11-inheritance.md))
- **Package**: a folder of classes, like `frc.robot.mechanisms`. ([Lists](ch01-19-lists.md))
- **Parameter**: a value a method or constructor needs to be handed when it's called. ([Constructors](ch01-05-constructors.md))
- **Parent class**: the class that a child class `extends`. ([Inheritance](ch01-11-inheritance.md))
- **Primitive**: one of Java's built-in simple types, like `int`, `double`, and `boolean`. ([Variables](ch01-02-variables.md))
- **`private`**: only usable inside its own class. **Default** (nothing written): usable in the same folder. **`protected`**: the same folder plus child classes anywhere. **`public`**: usable anywhere. ([Protecting Your Fields](ch01-12-protecting-your-fields.md))
- **Quick Fix**: VS Code's suggestions for fixing a red squiggly line, like adding a missing `import`. ([Lists](ch01-19-lists.md))
- **Red squiggly line**: how VS Code marks a mistake it can spot before your program runs. ([Your First Program](ch01-01-first-program.md))
- **Scope**: the part of the code where a variable exists, from where it's made to the `}` that closes its block. ([If Statements](ch01-07-if-statements.md))
- **Stack trace**: what Java prints when it crashes: what went wrong, and the list of methods that led there. ([Finding Bugs](ch02-10-finding-bugs.md))
- **`static`**: belongs to the class itself, instead of to each object. ([Static and Constants](ch01-13-static-and-constants.md))
- **`String`**: a type for text. ([Variables](ch01-02-variables.md))
- **Switch**: picks what to do based on which value something is, like which enum choice. ([Enums](ch01-17-enums.md))
- **Ternary operator**: `question ? a : b`, which picks `a` if the question is `true`, and `b` if it's `false`. ([More Decisions](ch01-08-more-decisions.md))
- **`this`**: the object a method was called on. ([Objects Inside Objects](ch01-10-objects-inside-objects.md), [Lambdas](ch01-16-lambdas.md))
- **`toString`**: the method Java calls to turn an object into text. ([Protecting Your Fields](ch01-12-protecting-your-fields.md))
- **`try` and `catch`**: run some code, and handle an exception if it throws one, instead of crashing. ([Finding Bugs](ch02-10-finding-bugs.md))
- **Type**: what kind of value a variable holds, like `int` or `Player`. ([Variables](ch01-02-variables.md))
- **Variable**: a named place to keep a value. ([Variables](ch01-02-variables.md))
- **`while` loop**: a loop that keeps going as long as a question is `true`. ([Loops](ch01-18-loops.md))

## Robot code

- **Absolute encoder**: an encoder that always knows the real angle, even right after turning on. A **relative encoder** starts at 0 every time. ([Real Hardware](ch02-11-real-hardware.md))
- **AdvantageScope**: the app we use to graph and watch telemetry. ([Mechanisms and Commands](ch02-02-mechanisms-and-commands.md))
- **Alliance**: red or blue. Each match has three robots on each alliance. ([Enums](ch01-17-enums.md), [Driving](ch02-09-driving.md))
- **AprilTag**: a black-and-white square on the field that cameras use to work out where the robot is. ([What's Next](ch02-14-whats-next.md))
- **Autonomous**: the first part of a match, when the robot runs by itself. ([Autonomous](ch02-05-autonomous.md))
- **Beam break**: a sensor that shines a light across a gap, and notices when something blocks it. ([Sensors and an Intake](ch02-08-sensors-and-an-intake.md))
- **Brake mode** and **coast mode**: whether a motor resists turning or spins freely, when it's told 0 volts. ([Real Hardware](ch02-11-real-hardware.md))
- **Brownout**: when the battery voltage drops so low that the robot shuts things off to protect itself. ([Real Hardware](ch02-11-real-hardware.md))
- **CAN bus** and **CAN ID**: the wires the robot controller uses to talk to motor controllers and sensors, and the number that tells each device apart. ([Real Hardware](ch02-11-real-hardware.md))
- **`ChassisVelocities`**: how fast the robot should drive in x and y, and how fast it should turn. ([Driving](ch02-09-driving.md))
- **Characterization**: using WPILib's **SysId** tool to measure how a mechanism responds, and work out its feedforward gains from that. ([What's Next](ch02-14-whats-next.md))
- **Command**: one thing for the robot to do, like moving the arm to a position. ([Mechanisms and Commands](ch02-02-mechanisms-and-commands.md))
- **Command palette**: VS Code's search box for everything it can do, opened with Ctrl+Shift+P. ([Your First Robot Project](ch02-01-first-robot-project.md))
- **Coroutine**: how a command talks to the scheduler: yielding, waiting, and awaiting other commands. ([Loops](ch01-18-loops.md), [Your First Robot Project](ch02-01-first-robot-project.md))
- **Current limit**: a cap on how much electricity a motor can pull. ([Real Hardware](ch02-11-real-hardware.md))
- **Deadband**: a small range around 0 where a joystick counts as exactly 0. ([Controllers and Teleop](ch02-04-controllers-and-teleop.md))
- **Default command**: the command a mechanism runs when nothing else is using it. ([Mechanisms and Commands](ch02-02-mechanisms-and-commands.md))
- **Deploying**: sending your code to the real robot. ([Real Hardware](ch02-11-real-hardware.md))
- **Drivetrain**: the wheels, and the motors that drive them. ([Driving](ch02-09-driving.md))
- **Driver Station**: the program the drive team uses to run the robot. ([Real Hardware](ch02-11-real-hardware.md))
- **Encoder**: a sensor that measures how far something has turned. ([Protecting Your Fields](ch01-12-protecting-your-fields.md))
- **Error**: how far a mechanism still has to go: target minus where it is now. ([Feedback Control](ch02-07-feedback-control.md))
- **Feedback control**: measuring how far off a mechanism is, and using that to decide how hard to push. ([Feedback Control](ch02-07-feedback-control.md))
- **Feedforward**: working out ahead of time what a mechanism needs, like how hard to push to hold it up against gravity. ([Simulating an Arm](ch02-06-simulating-an-arm.md), [Feedback Control](ch02-07-feedback-control.md))
- **Field-relative** and **robot-relative**: directions measured by the field or by which way the robot is facing. ([Driving](ch02-09-driving.md))
- **Gains**: the numbers that control how a PID controller or feedforward behaves, like `KP` and `KG`. ([Feedback Control](ch02-07-feedback-control.md))
- **Gyro**: a sensor that measures which way the robot is facing. ([Protecting Your Fields](ch01-12-protecting-your-fields.md))
- **Hard stop** and **soft limit**: the piece of metal a mechanism can't move past, and a limit in the code that stops it before it gets there. ([Simulating an Arm](ch02-06-simulating-an-arm.md), [Real Hardware](ch02-11-real-hardware.md))
- **Intake**: the part of a robot that picks up game pieces, usually with spinning **rollers**. ([Sensors and an Intake](ch02-08-sensors-and-an-intake.md))
- **Inverted**: a motor setting that flips which way it spins. ([Real Hardware](ch02-11-real-hardware.md))
- **IO**: the interface between a mechanism and its hardware, with a real version and a simulated version. ([Interfaces](ch01-15-interfaces.md), [Mechanisms and Commands](ch02-02-mechanisms-and-commands.md))
- **Limit switch**: a button that a mechanism presses at the end of where it can move. ([Sensors and an Intake](ch02-08-sensors-and-an-intake.md))
- **Mechanism**: a part of the robot that moves, like an arm or the drivetrain. ([Your First Robot Project](ch02-01-first-robot-project.md))
- **`Mechanism2d`**: a simple drawing of a mechanism, made of lines called **ligaments**. ([Simulating an Arm](ch02-06-simulating-an-arm.md))
- **Moment of inertia**: how hard something is to get spinning. ([Simulating an Arm](ch02-06-simulating-an-arm.md))
- **Motion profile**: a plan for a smooth move: speed up, cruise, and slow down. ([Feedback Control](ch02-07-feedback-control.md), [What's Next](ch02-14-whats-next.md))
- **Motor controller**: the device that decides how much power goes to a motor. ([Real Hardware](ch02-11-real-hardware.md))
- **Odometry**: working out where the robot is by adding up how far its wheels have turned. ([Driving](ch02-09-driving.md))
- **Opmode**: one way of running the robot, like a teleop mode or an autonomous routine. ([Your First Robot Project](ch02-01-first-robot-project.md))
- **Operator**: the second driver, who runs everything but the drivetrain. ([Driving](ch02-09-driving.md))
- **Origin**: the (0, 0) corner of the field, on the right as you stand behind the blue alliance's wall. ([Driving](ch02-09-driving.md))
- **Path**: a smooth route for the robot to drive, planned ahead of time in an app like PathPlanner or Choreo. ([Driving](ch02-09-driving.md), [What's Next](ch02-14-whats-next.md))
- **PID**: feedback control that adds up a **P**roportional, an **I**ntegral, and a **D**erivative part. ([Feedback Control](ch02-07-feedback-control.md))
- **Pose**: where the robot is on the field, and which way it's facing, as a `Pose2d`. ([Driving](ch02-09-driving.md))
- **Preload**: the game piece a robot holds at the start of a match. ([Sensors and an Intake](ch02-08-sensors-and-an-intake.md))
- **Priority**: which commands can cancel which. A command can only take over from one with the same or lower priority. ([Mechanisms and Commands](ch02-02-mechanisms-and-commands.md))
- **Requirement**: the mechanism a command uses. Only one command can require a mechanism at a time. ([Mechanisms and Commands](ch02-02-mechanisms-and-commands.md))
- **Robot controller**: the robot's computer, which runs our code. Starting in 2027, it's **Systemcore**. ([Real Hardware](ch02-11-real-hardware.md))
- **Scheduler**: the part of WPILib that runs commands, giving each one a turn about 50 times a second. ([Your First Robot Project](ch02-01-first-robot-project.md))
- **Sensor**: anything that lets the robot measure the world. ([Sensors and an Intake](ch02-08-sensors-and-an-intake.md))
- **Simulation**: running robot code on a laptop, with pretend motors and sensors. ([Robot Code](ch02-00-robot-code.md))
- **Swerve drive**: a drivetrain whose wheels can each point in any direction. Each corner is a **swerve module**, with one motor to spin the wheel and one to steer it. ([Driving](ch02-09-driving.md))
- **Telemetry**: information the robot sends back for you to look at. ([Mechanisms and Commands](ch02-02-mechanisms-and-commands.md))
- **Teleop**: the part of a match when drivers control the robot. ([Your First Robot Project](ch02-01-first-robot-project.md))
- **Tolerance**: how close counts as "close enough," like an arm being within 2 degrees of its target. ([Decimals and Math](ch01-14-decimals-and-math.md))
- **Trigger**: a condition that can start and stop commands, like a button being pressed. ([Lambdas](ch01-16-lambdas.md), [Controllers and Teleop](ch02-04-controllers-and-teleop.md))
- **Tuning**: finding good gains by trying them and watching what happens. ([Feedback Control](ch02-07-feedback-control.md))
- **Unit tests**: small programs that check your code automatically every time it builds. ([What's Next](ch02-14-whats-next.md))
- **Units**: types like `Angle` and `Distance` that know what they're measured in. ([Units](ch02-03-units.md))
- **Vendor library**: code from a company that makes motors or sensors, like REVLib or Phoenix 6. ([Real Hardware](ch02-11-real-hardware.md))
- **Voltage**: how hard the battery pushes electricity through a motor. ([Simulating an Arm](ch02-06-simulating-an-arm.md))
- **Yield**: a command saying "that's all for now," so the rest of the robot gets a turn. ([Loops](ch01-18-loops.md))

## Working together

- **Branch**: a separate line of commits, so you can work without changing anyone else's code. The shared one is **`main`**. ([Working Together](ch02-12-working-together.md))
- **Clone**: make a copy of a repo on your laptop. ([Your First Program](ch01-01-first-program.md#saving-your-work), [Working Together](ch02-12-working-together.md))
- **Commit**: a saved snapshot of the code, with a message saying what changed. ([Your First Program](ch01-01-first-program.md#saving-your-work), [Working Together](ch02-12-working-together.md))
- **Git** and **GitHub**: the program that keeps track of every change to the code, and the website that stores it online, where you and the team can get to it. ([Your First Program](ch01-01-first-program.md#saving-your-work), [Working Together](ch02-12-working-together.md))
- **Issue**: a task or bug, written down on GitHub with a number. ([Working Together](ch02-12-working-together.md))
- **Merge**: add one branch's commits into another. A **merge conflict** is when two branches changed the same lines, and Git needs you to pick. ([Working Together](ch02-12-working-together.md))
- **Pull request**: a request to merge your branch into `main`, where teammates review it first. ([Working Together](ch02-12-working-together.md))
- **Push** and **pull**: send your commits to GitHub, and bring down commits from GitHub that you don't have yet. ([Your First Program](ch01-01-first-program.md#saving-your-work), [Working Together](ch02-12-working-together.md))
- **Repository**: a project that Git keeps track of, with its whole history. ([Your First Program](ch01-01-first-program.md#saving-your-work), [Working Together](ch02-12-working-together.md))
- **Staging**: picking which changed files go into your next commit. ([Working Together](ch02-12-working-together.md))
